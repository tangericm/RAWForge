RAWForge — station flow

A throwaway prototype for issue #10, rebuilt against the simplification pass. Not production code.

The question this answers A station is a pose, and it may hold several capture sets across the three rear sensors. Under the simplification pass there is exactly one failure rule: a hard fault flags, aborts the station, and deletes that station's frames — stations already banked survive. Does that hold up? Watch two things: the frame count on disk when a station aborts, and the fact that the session file stays silent until a station completes. The log's write unit and the abort unit are the same thing, which is why nothing partial ever needs interpreting.

      The lower pane is memory, not disk. Everything in it is lost when a station aborts or the phone dies, and that is the design rather than a limitation: a station either completed or never existed, so there is no partial record to reconcile later. Clipping statistics are computed and recorded but never judged — no verdict, no prompt, no re-shoot. Calibration sessions are the one carve-out and are not modelled here: a dark run has no poses, so it aborts by capture set rather than losing the whole run (#15).
